把字节跳动 `Seed大模型人才实习招聘` 这一栏从头翻一遍，很容易先被岗位数量吓到。页面上挂着 `80` 个职位，看起来像一整面职位墙，但真正把标题、职责和要求逐条对过之后，会发现里面有相当一部分其实是同一份 JD 在不同 base 城市重复发布。

这篇文章做的事情很简单：把这批岗位重新按 **完整 JD** 去重，不再按“列表页一条算一条”来数，而是按“真正不同的岗位说明”来数。处理完以后，原始 `80` 个职位被压到 `34` 组唯一 JD，剩下的差异主要集中在城市、职位 ID 和少量同名但内容不同的岗位上。

如果你的目标不是机械地海投，而是想先看清楚这轮招聘到底在招哪些方向、哪些岗位是全国多地复用、哪些岗位虽然标题一样但实际上不是同一份 JD，这种整理方式会比直接看官方列表更省时间。

## 去重规则

这次合并不是按标题去重，而是按下面四项同时完全一致来合并：

- `岗位标题`
- `JD 职责 description`
- `任职要求 requirement`
- `岗位方向 category`

只要这四项完全一致，即使 base 城市不同，也归为同一组。

这也意味着一件事：**同名岗位不一定会被合并**。比如同样叫“AI搜索Agent算法实习生”，如果职责或要求有变化，它仍然会保留成两组。

- 重复压缩率：`57.5%`

- 单城市独有 JD 组数：`6`

### 城市分布

- 原始岗位数：
  - 北京：`33`
  - 上海：`27`
  - 深圳：`12`
  - 杭州：`8`

  - 北京：`33`

  - 深圳：`12`

这里的“合并后 JD 覆盖城市数”不是岗位条数，而是有多少份唯一 JD 覆盖到这个城市。北京几乎覆盖了全部岗位面，上海也非常接近，深圳和杭州则更像是部分方向的扩展点。

## 几个值得先记住的观察

- 这轮岗位并不是“80 个完全不同的坑位”，更接近“34 份核心 JD 在多城市展开”。
- 算法岗占比最高，而且覆盖的主题不是泛泛的 LLM，而是拆成了搜索 Agent、语音、音频多模态、多模态世界模型、评测、强化学习、Edge 模型等更具体的方向。
- 北京和上海是最完整的两个 base，很多岗位是双城同时开；深圳更集中在视频、视觉、多模态和部分模型算法；杭州更多出现在音频、多模态和系统侧岗位。
- 有些岗位标题完全一样，但职责并不完全一样，不能只靠标题判断是不是一回事。

## 这份整理怎么用会更有效

如果是投递前快速判断，我会建议按下面的顺序看：

- 先看覆盖 `3-4` 个城市的 JD，它们通常更像这轮招聘里的核心坑位
- 再看自己关心的方向里，北京和上海是否同时开岗，这通常能反映团队规模和招聘强度
- 同名岗位先别默认当成同一份 JD，尤其是搜索 Agent 这类标题高度相似的岗位，最好还是看职责和要求有没有变化
- 如果你本身更偏系统、训练推理优化或 infra，不要只盯算法标签，Seed 这批岗位里基础架构和机器学习系统侧也有独立需求
